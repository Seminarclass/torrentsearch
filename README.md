# TorrentSearch

A **self-hosted torrent search engine** that scrapes public torrent indexes directly — **no third-party APIs**. The frontend is a static site hosted on **GitHub Pages**; the data is refreshed hourly by a **GitHub Actions** workflow that commits fresh results back to the repo.

```
┌─────────────────┐      ┌────────────────────────────┐      ┌──────────────┐
│  GitHub Pages   │ ───► │  /api/search (optional)    │ ◄─── │  Self-hosted │
│  Static SPA     │      │  Self-hosted Node backend   │      │  Node server │
└─────────────────┘      └────────────────────────────┘      └──────────────┘
        │                           │                                  │
        │                           │           ┌──────────────────────┐│
        └────── reads ◄─────────────┘           │  GitHub Actions       ││
                data/latest.json               │  every 1h: scrape    ─┘│
                (refreshed by Actions)         │  → commit latest.json │
                                               └──────────────────────┘
```

## ✨ Features

- **Zero third-party APIs** — every provider scrapes its own data via hand-written parsers
- **8+ built-in providers** — 1337x, Nyaa, YTS, Knaben, Internet Archive, BitSearch, TokyoToshokan, TorrentDownload
- **Deduplication** — the same torrent found by multiple providers is merged, picking the highest-seeder copy
- **Magnet-link copy** with one click
- **Beautiful dark/light UI** with animated background, gradient text, and category chips
- **Two deployment modes** — fully self-hosted backend, or pure GitHub (Actions scrapes hourly)
- **Mock-tested** — `node server/test/mock.test.js` exercises the orchestrator without network

## 🚀 Quick Start (local)

```bash
git clone https://github.com/Seminarclass/torrentsearch.git
cd torrentsearch
npm install

# Option A: run the backend (real-time scraping)
PORT=4000 node server/index.js
# In another terminal, serve the frontend:
python3 -m http.server 8080
# Open http://localhost:8080  (the status pill will say "8 providers live")
```

```bash
# Option B: scrape to data/latest.json and serve the static frontend only
node server/scrape.js
python3 -m http.server 8080
# Open http://localhost:8080  (the status pill will say "cache mode")
```

## ☁️ GitHub-Only Deployment

This is the path with **zero hosting cost** and **zero Cloudflare** — just GitHub.

1. **Push the repo to GitHub:**
   ```bash
   git remote add origin https://github.com/Seminarclass/torrentsearch.git
   git push -u origin main
   ```

2. **Enable GitHub Pages:**
   - Repo → Settings → Pages → Source: **GitHub Actions**

3. **Done.** The `scrape-and-deploy` workflow will:
   - Run every hour
   - Scrape all providers with a list of common queries
   - Commit the fresh `data/latest.json` back to the repo
   - Re-deploy the static site

4. **Open the site at** `https://<your-username>.github.io/torrentsearch/`

The frontend automatically detects whether a backend is reachable; if not, it falls back to the cached `data/latest.json` (refreshed hourly by Actions).

## 🧠 How the providers work

Each provider in `server/providers/` is a self-contained class with:

- `id` — short slug (`1337x`, `nyaa`, …)
- `name` — display name
- `url` — canonical homepage
- `categories` — what kinds of content it indexes
- `search(query, category)` — returns `[]` on failure, never throws

We use **only Node.js built-ins** (`http`, `https`, `zlib`, `url`) and hand-written regex parsers. No `cheerio`, `axios`, or `node-fetch`.

## 🧪 Tests

## 🔌 API (when running the backend)

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/health` | `{ ok: true, providers: 8 }` |
| `GET` | `/api/providers` | List of all providers with metadata |
| `GET` | `/api/search?q=<query>&category=<cat>&limit=80` | Search across all providers, deduped, sorted by seeders |

Response example:
